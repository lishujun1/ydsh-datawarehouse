# 指标定义文档

## 一、核心指标口径

| 指标 | 口径 | 计算式 |
|---|---|---|
| GMV | 所有有效订单实付金额之和 | sum(pay_amount)，排除 NULL |
| 订单量 | 去重订单数 | count(distinct order_id) |
| 客单价 AOV | GMV ÷ 订单量 | sum(pay_amount)/count(distinct order_id) |
| 活跃用户数 | 有下单行为的去重用户数 | count(distinct user_id) |
| 复购率 | 下单≥2次用户数 ÷ 下单用户数（均按 user_id 去重，仅计 pay_amount 非空订单） | count(distinct case when cnt>=2 then user_id end) / count(distinct user_id) |
| 品类销售占比 | 品类销售额 ÷ 总GMV（**注意：品类销售额为明细行口径，与订单口径 GMV 不可直接加总**） | 窗口或子查询 |

> **复购率备注**：模拟数据中复购率为 100%（人均 14.4 单），属数据构造特征；真实业务通常 20%~40%。早期版本因分子 `sum(case when cnt>=2 then 1 else 0 end)` 在 join 后被放大 frequency 倍，得出 14.398% 的错误值，已修正为 `count(distinct case when cnt>=2 then user_id end)`，详见 `AI智能洞察报告.md` 第 4 节。

## 二、口径差异说明（重要）

以下指标存在**多口径并存**的情况，使用时须明确标注，不可混用：

| 指标 | 口径 A | 口径 B | 差异原因 | 使用建议 |
|---|---|---|---|---|
| **品类销售额 vs GMV** | 明细行：`sum(quantity × unit_price × (1 - discount))` | 订单：`sum(pay_amount)` | 订单级优惠未摊分到明细行；明细为价税合计，订单为实付 | GMV 用订单口径；品类排行用明细口径；**两者不可加总或直接比较** |
| **客单价** | 含 NULL 订单：2407.78 | 有效订单：2508.45 | 602 条异常金额置 NULL（占 4.01%） | 对外报有效订单口径，并注明"已排除异常金额" |
| **复购率** | ADS 层固化：100% | NL2SQL 即时：100% | 修正后两者一致；旧版 ADS 曾误算 14.398% | 以 ADS 层为准；NL2SQL 作链路验证 |
| **订单状态编码** | 1=待支付, 2=已支付, 3=退款中, 4=已取消 | 字典未明确定义 | 按数据字典示例推断 | 标注"待业务方确认"，见 `数据质量对比报告` 遗留问题 2 |

## 三、枚举值域

| 字段 | 规范值域 | 来源 |
|---|---|---|
| order_status | 待支付 / 已支付 / 已完成 / 已取消 / 退款中 | `clean_enum.sql` 映射 |
| pay_type | 支付宝 / 微信支付 / 银行卡 / 货到付款 | `clean_enum.sql` 映射 |
| channel | APP / 小程序 / PC / 门店 | `clean_enum.sql` 映射 |
| member_level | 普通会员 / 银卡会员 / 金卡会员 / 钻石会员 | `clean_enum.sql` 映射 |
| gender | 男 / 女 / 未知 | `clean_enum.sql` 映射 |
| behavior_type | 浏览 / 收藏 / 加购 / 购买 | `clean_enum.sql` 映射 |

> **编码映射依据**：`order_status` 的数字编码 1/2/3/4 按数据字典示例推断（1=待支付、2=已支付、3=退款中、4=已取消），尚未与业务方正式确认，已在 `数据质量对比报告` 遗留问题中标注。

## 四、数据范围与基准

| 项目 | 值 | 说明 |
|---|---|---|
| 数据时间范围 | 2024-01-01 至 2024-12-31 | 366 天 |
| RFM 基准日 | 2024-12-31 | `ads_user_value.recency` 计算基准，固定为数据截止日 |
| 有效订单定义 | `pay_amount is not null` | 排除 602 条异常金额（300 负 + 302 超大） |
| 异常金额阈值 | `pay_amount < 0 or pay_amount > 100000` | 依据 P95≈4833 与业务判断，置 NULL 保留行数 |
