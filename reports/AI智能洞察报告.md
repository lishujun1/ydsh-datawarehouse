# AI 智能洞察报告

## 1 异常归因（2024-01-20 GMV 断崖式下跌）

### 1.1 异常识别

2024-01-20 GMV = 50,273.3，环比下降 \(63.0\%\)（前一日约135,873），远超正常日间波动范围（\(\pm 10\% \sim 20\%\)），属重点异常。

### 1.2 数据一致性问题（关键前提）

渠道表为全年累计（四渠道合计约 3,611 万）、品类表为全年累计且属明细行口径（Top10 合计约 5.08 亿），与当日单日订单口径 GMV 50,273.3 **时间范围和口径均不同，不可直接横向比较**；本节归因聚焦当日 GMV 的环比异动，结构性数据仅作参考。

> **口径说明（补充）**：
> - 渠道 GMV 与当日 GMV 同属订单口径（`sum(pay_amount)`），量级差异源于**聚合范围**：渠道表为全年累计，当日表为单日。
> - 品类销售额为**明细行口径**（`quantity × unit_price × (1 - discount)`），未摊分订单级优惠，与订单口径 GMV **不可直接加总或比较**。
> - 详见 `指标定义.md` 口径说明表。

### 1.3 可能原因（按优先级）

| 优先级 | 假设 | 依据 | 验证方式 |
|---|---|---|---|
| 1 | 数据口径/回流问题 | 渠道、品类与当日 GMV 量级差数百倍 | 核对 GMV 定义、数据更新时间、去重逻辑 |
| 2 | 基准日虚高（大促后回落） | 63% 跌幅符合活动脉冲特征 | 拉取近 30 日 GMV 曲线，标注活动日 |
| 3 | 全渠道流量/转化普跌 | 品类结构平滑、无单点塌陷 | 拆分 UV、转化率、客单价 |
| 4 | 周末效应 | 1/20 为周六 | 对比历史周末/工作日均值 |
| 5 | 外部竞争/运营中断 | 需外部信息 | 排查投放、库存、竞品动态 |

### 1.4 分析局限

- 口径不一致是根本局限，渠道/品类与当日GMV无法交叉验证；
- 缺少过程指标（UV、转化率、客单价、退款率）；
- 仅一个环比点，无法判断是单日脉冲还是趋势下滑；
- 渠道数据分布过于均匀，疑似非单日真实数据；
- 外部因素不可观测。

建议：优先核对数据口径与回流完整性，再拉取近30日GMV \(^+\) 流量 \(^+\) 转化 \(^+\) 客单价四指标曲线，按"流量 \(\times\) 转化 \(\times\) 客单价"拆解定位。

## 2 经营分析摘要

本期核心KPI：

- GMV: 36,116,687.06
- 订单数：14,398笔
- 客单价（AOV）：2,508.45
- 活跃用户数：1,000人
- 复购率：100%（1.0）

数据关系校验：客单价2,508.45 \(\times\) 订单数14,398 \(\approx\) GMV36,116,687.06，数据内部一致性良好。活跃用户1,000人对应订单14,398笔，人均下单约14.4笔。

整体呈现"用户规模较小（1,000人）、客单价较高（2,508元）、复购率100%"的结构特征。复购率100%源于模拟数据中每位用户均产生多笔订单（人均14.4单），属数据构造特征，非真实业务复购水平；真实场景下该指标通常显著低于此值（新零售行业约20%~40%）。

## 4 复购率口径说明

- **ADS 层固化口径**：`ads_core_kpi.repurchase_rate = 1.0`（100%）
  - 分母：全量下单用户数，`count(distinct user_id)`，仅计 `pay_amount is not null` 的订单
  - 分子：下单≥2次的去重用户数，`count(distinct case when cnt>=2 then user_id end)`
  - SQL 见 `sql/ads/create_ads.sql` 第①段

- **修正记录**：
  早期版本分子误用 sum(case when u.cnt>=2 then 1 else 0 end)，该 sum 对 join 后的每个订单行计 1，用户有 N 单就计 N 次，导致分子被放大 N 倍，得出 14.398% 的错误值。

- **业务解读**：
  模拟数据集中 1,000 名下单用户人均产生 14.4 笔订单，全部满足"下单≥2次"，故复购率为 100%。该值反映的是**模拟数据的构造特征**，不代表真实业务复购水平；真实新零售场景下复购率通常为 20%~40%。若用于真实业务决策，需以实际用户行为数据重算。

- **NL2SQL 即时计算**：
  NL2SQL 临时 SQL 同样返回 1.0，与修正后 ADS 层一致，说明 NL2SQL 链路在复购率指标上口径正确。早期报告中"NL2SQL 1.0 与 ADS 14.398% 不一致"的判断，实为 ADS 旧版 SQL 错误，NL2SQL 结果反而正确。

- **口径统一结论**：
  以 ADS 层修正后值 100% 为准；NL2SQL 结果作为链路一致性验证，与 ADS 层一致；旧值 14.398% 仅作为修正过程记录保留，不再作为业务口径。
